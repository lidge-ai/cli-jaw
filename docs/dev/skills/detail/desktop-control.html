Desktop Control Default Active

Use the Computer Use tool for desktop apps and browser chrome. Use jaw browser for ordinary page DOM work.

Skill ID: desktop-control
Surface: jaw-computer-use MCP server, tool js; Codex uses its native Computer Use plugin
Host: macOS or Windows with the Codex desktop plugin cache

Choose the surface

Computer Use is an MCP tool, not an employee. Jaw registers jaw-computer-use for MCP-aware CLIs except Codex. Claude exposes it as mcp__jaw-computer-use__js. A Codex boss or employee uses Codex's native Computer Use plugin. A long GUI task may be delegated to any employee that has one of these surfaces.

For web DOM content, use jaw browser snapshot --interactive and the resulting refs. Desktop app windows, browser chrome, OS dialogs, and non-DOM pixels use Computer Use when available. An explicit $computer-use request must use Computer Use; never silently substitute CDP.

First call and actions

Call the exposed js tool once and read its returned documentation. Follow only the API described there. It defines the cua object, including cua.getApp(name), app.getAXState(), app.click(index|[x,y]), app.typeText, and app.pressKey. Read current app state before targeting an element and refresh it after UI changes.

// Inside the documented Computer Use js tool
let app = await cua.getApp("Finder");
let state = await app.getAXState();
// Choose an index from the current state before calling app.click(index).

CDP Path — cli-jaw browser

For anything addressable by Chrome DOM: page text, form fields, buttons inside the page. 10x faster than Computer Use for web content.

Session Commands

cli-jaw browser status                         # is a session active?
cli-jaw browser start --agent                  # headless automation session
cli-jaw browser start --headless               # manual headless (WSL/CI/Docker)
cli-jaw browser start                          # visible window (only if user asks)
cli-jaw browser navigate "https://example.com" # go to URL
cli-jaw browser open "https://example.com"     # open in new tab
cli-jaw browser tabs                           # list tabs

Snapshot + Act

cli-jaw browser snapshot --interactive   # list clickable elements (e1, e2, ...)
cli-jaw browser click e3                 # click by ref
cli-jaw browser type e5 "query" --submit # type + Enter
cli-jaw browser press Enter              # fallback key press
cli-jaw browser screenshot               # save a PNG
cli-jaw browser text                     # dump visible text
Ref IDs reset after every navigate. Always re-snapshot after navigating to a new page.

Setup and failures

Install and open the ChatGPT desktop app with Computer Use, then restart jaw so it registers jaw-computer-use. Jaw resolves the newest bundled cua_repl from the desktop plugin cache. On macOS, the responsible process or binary that launched the jaw service may need permission to access data from other apps (TCC App Data for the ChatGPT Computer Use container). Grant this under Privacy & Security; the exact pane name varies by macOS version. A Terminal-launched jaw without that grant can block on the first app call. On Windows the same mechanism requires the desktop plugin cache. Linux, WSL, and Docker have no host Computer Use surface.

Jaw answers Computer Use app-approval prompts from the run's permission policy: auto approves; safe declines and reports not approved.
